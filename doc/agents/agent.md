# Agent 工作规范

本文档是根目录 `AGENTS.md` 的项目文档版，用于说明本项目中 AI Agent、开发 Agent 与叙事系统的工作边界。

## 核心结论

本项目的关键不是让 NPC “更会聊天”，而是让 NPC 在可控世界状态中表现出可信的记忆、动机、关系和隐瞒行为。因此，LLM 必须被约束在“表达与意图生成”层，不能成为世界状态的直接写入者。

## Agent 职责边界

- NPC Agent 负责生成符合角色身份、记忆、目标和关系状态的回应。
- Narrative Director 负责限制可说内容、检查剧透风险、维护案件真相和悬疑节奏。
- Rule Engine 负责校验 Agent 提出的行为意图，并执行真实状态变化。
- Game Backend 负责持久化世界状态、角色状态、事件日志、关系网络和剧情阶段。
- Web Client 只负责展示与交互，不承担权威状态判断。

## 开发 Agent 工作要求

- 修改代码前，先明确变更会影响哪个层：客户端、后端、Agent、导演系统或规则系统。
- 每次更新涉及架构、接口、模型、规则或叙事逻辑时，必须同步更新 `doc` 目录下的文档。
- 发现设计问题时直接指出根因，提出可落地的最佳方案，不以临时兜底替代正确设计。
- 对生产风险保持敏感，优先保证状态一致性、可测试性、可回放性和可审计性。

## NPC Agent 输出规范

NPC Agent 的输出必须是结构化结果，至少包含：

- `speech`：展示给玩家的自然语言回复。
- `intent`：NPC 的行为意图，例如回答、隐瞒、撒谎、试探、拒绝、反问、转移话题。
- `emotional_shift`：可能产生的情绪变化。
- `proposed_actions`：NPC 希望触发的行为，但不代表真实执行。
- `memory_refs`：影响本次输出的记忆来源。

`proposed_actions` 必须交由 Rule Engine 校验。校验失败时，系统应拒绝、降级或改写该行为，而不是信任 LLM。

## 叙事安全规则

- NPC 不得透露当前剧情阶段尚未释放的关键真相。
- NPC 不得知道其角色视角之外的信息。
- NPC 可以说谎，但谎言必须符合角色动机、已知信息和当前压力。
- NPC 可以记错或误解，但必须能追溯到记忆、传闻或事件来源。
- 案件核心真相必须由 Narrative Director 和规则系统共同保护，不得被 LLM 重写。

## 事件与记忆规则

- 玩家行为、NPC 行为、对话摘要和状态变化都必须写入事件日志。
- 长期记忆必须从事件中生成，并保留来源引用。
- 关系变化必须可解释，不能只留下不可追踪的数值变化。
- 固定事件序列应能回放出一致的世界状态。

## 测试重点

- 验证 LLM 输出不能绕过规则系统修改状态。
- 验证未解锁线索不会被 NPC 提前说出。
- 验证同一组事件可以稳定重建角色关系和剧情阶段。
- 验证 mock LLM 响应下的 Agent 链路可重复测试。
- 验证非法行为意图会被拒绝或降级处理。
